# Локальная разметка спикеров (диаризация) — дизайн

Дата: 2026-10-09. Версия скилла после реализации: v0.5.0.

## Зачем

С v0.4.0 по умолчанию работает локальный провайдер `local` (Parakeet Ultra через
parakeet.cpp), но спикеров он не размечает. Разметку дают только свой whisperx-сервер или
ничего. Для подкастов, интервью и созвонов это главный пробел: саммари не может сказать, кто
что утверждал.

Цель — разметка спикеров у `local` без сервера и без ключей, на тех же машинах (Metal, Vulkan,
CPU). **whisperx остаётся равноправным вторым путём со спикерами** — для тех, у кого уже есть
сервер. Это не замена, а два варианта.

## Решение: гибрид «текст + отдельная диаризация»

Модель [nvidia/Nemotron-3-Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization)
(Sortformer, до 8 спикеров, лицензия [OpenMDW 1.1](https://openmdw.ai/license/1-1/)) в
GGUF-конвертации `mudler/parakeet-cpp-gguf`. Её запускает тот же `parakeet-cli` v0.6.1, что
уже стоит: новых бинарников нет.

Два прохода движка по одному wav:
1. `parakeet-cli transcribe --vad --json` — слова с пунктуацией и таймкодами (как в v0.4);
2. `parakeet-cli scene --diar <diar.gguf> --input <wav> --json` без `--model` — только
   сегменты «кто когда говорил».

Каждое слово получает спикера по пересечению во времени; дальше — существующий конвейер
cues → абзацы → `transcript.md` с `**Speaker N:**`.

### Проба (2026-10-08 и 2026-10-09, Linux x64, RTX 5060 Ti)

- 75-минутный русский подкаст, два спикера, эталон — разметка whisperx: гибрид дал **92.1%**
  совпадения по словам, пунктуация сохраняется. По 10-минутным окнам — 87–98%. Расхождения
  при просмотре похожи на ошибки эталона (whisperx размечает целыми абзацами).
- `scene` с `--model` (текст и спикеры за один проход) — те же 92.1%, но теряет пунктуацию
  в ~40% реплик и выдаёт `<unk>`. **Для текста не используем.**
- q8_0 и f16 дали одинаковый результат — берём q8_0 (108 МБ против 201 МБ). Карточка модели
  оговаривает, что q8_0 изредка разрывает сегмент на одном кадре; на привязку слов это не
  влияет.
- Предупреждение документации parakeet.cpp про офлайн-режим (22% на 12 минутах) относится к
  офлайн-пути, а `scene` — потоковый.
- Скорость только диаризации: 75 мин на Vulkan — 6.8 с; 525 с на Vulkan — 1.1 с, на CPU
  (16 потоков, `scene` сам берёт ~7 ядер) — 6.8 с (~77×). В пробе на 75 минутах CPU давал
  ~16×; поэтому скорость меряется на машине, а по умолчанию берётся осторожное значение.
- На 525-секундном ролике второй спикер говорит 30 с из 485 (~6%) — порог «шумовых»
  спикеров по доле речи опасен, его нет.

### Формат вывода `scene --json`

JSONL, событие каждые 0.2 с:

```json
{"t":525.212,"utterances":[],"words":[],"speakers":[{"speaker":1,"start":506.370,"end":508.890}],"sounds":[],"active":{"speakers":[],"sounds":[]}}
```

- `speakers` — сегменты, **закрывшиеся** к этому событию; каждый приходит ровно один раз.
  Номер спикера — с 0.
- `active.speakers` — открытые сегменты (только `start`); последнее событие закрывает всё
  оставшееся, поэтому `active` не нужен.
- stderr содержит `pk::Backend using device: Vulkan0` при работе на GPU — так же, как
  `transcribe`; существующее правило «Vulkan без устройства» применимо как есть.

## Что входит и что нет

Входит:
- модель диаризации в `local install` и `local status`;
- второй проход и привязка слов к спикерам в `src/local/`;
- ключ `diarize` у `type: "local"`; `--no-diarize` действует и на local;
- правило «один спикер — без меток» для local и whisperx;
- оценка времени и `--accept-slow` с учётом второго прохода;
- хвосты v0.4: докачка при обрыве в пределах запуска, подсказка `device: "cpu"` при
  Vulkan без устройства, предупреждения конфига в выводе `fetch`;
- доки, атрибуция модели.

Не входит: имена спикеров (реестр голосов `--speakers/--registry`), больше 8 спикеров,
диаризация вывода `openai-compatible`, возобновление загрузки между запусками, f16-модель,
проверка на macOS (её делает владелец репозитория).

## Установка и статус

### `local install`

- Качает недостающее: сборки, основную модель, **модель диаризации** — тем же `ensureModel`
  (проверка размера и sha256, атомарная замена, уборка `.part`).
- Результат: `{ version, builds, model: { path, bytes }, diar_model: { path, bytes }, downloaded_bytes }`.
- Агент перед запуском называет объём: ~0.9 ГБ модель + ~0.1 ГБ диаризация + бинарники
  (при обновлении с v0.4 — только ~0.1 ГБ).

### Докачка при обрыве (в пределах запуска)

`download` при сетевой ошибке или стопоре (idle-таймаут) во время чтения тела не сдаётся сразу:
- до **3 повторов**: новый запрос с `Range: bytes=<получено>-` в тот же `.part`, хэш
  продолжает считаться по уже полученным байтам;
- ответ `206` — дописываем; ответ `200` (сервер проигнорировал Range) — `.part` обнуляется,
  хэш сбрасывается, качаем с начала (это тоже попытка);
- HTTP-ошибка (не 2xx) на повторе — без дальнейших повторов, обычная ошибка `HTTP <code>`;
- ошибка до получения первого ответа (нет сети) тоже повторяется в пределах тех же 3 попыток;
- исчерпали попытки — прежняя ошибка `could not download <file>: <тег>`, `.part` удаляется;
- проверка размера и sha256 в конце — без изменений; превышение размера — `mismatch` сразу,
  без повторов.

Возобновление между запусками (стабильное имя `.part`, защита от параллельных install) — нет.

### `local status`

- `installed` не меняется: CPU-сборка + проверенная (по размеру) основная модель. Модель
  диаризации **не обязательна**: после обновления с v0.4 без `local install` local остаётся
  доступным, просто без спикеров.
- Новое поле `diarization: { present, verified, path }` (проверка по размеру).
- `hint` не меняется: `localMissing` читает его как признак «нужен libvulkan1».

### `check`

local установлен, а модели диаризации нет — в `deps.missing` **необязательный** пункт (как
`libvulkan1`, `depsOk` не нарушает):
`{ name: "diarization-model", install: "sh <skill-dir>/scripts/video-summary local install", needsSudo: false, note: "~0.1 GB download; enables speaker labels", optional: true }`.
local не установлен — пункта нет (его закроет обычный пункт `parakeet`, тот же `local install`).
`fetch` дополнительно сообщает о пропуске разметки через `asr_failed`.

## Конфиг

```json
{ "name": "local", "type": "local", "engine": "parakeet", "model": "ultra", "device": "auto", "diarize": true }
```

- `diarize`: `true` (по умолчанию) или `false`; не булево — ошибка валидации с путём к полю.
- `LocalProviderConfig.diarize: boolean`, `LocalProvider.diarize: boolean` (было `false`).
- Флаги CLI не меняются. Диаризация в прогоне = `!--no-diarize && provider.diarize`.

## Прогон (`src/local/parakeet.ts`, `src/local/diarize.ts`)

### Порядок

1. ogg → wav (как сейчас), один wav на оба прохода.
2. `transcribe` — как в v0.4: GPU, при сбое CPU; Vulkan без устройства → `device: "cpu"`.
3. Если диаризация включена и `paths.diarModel` на месте с пинованным размером —
   `scene --diar <diarModel> --input <wav> --json`:
   - **устройство — то, где фактически отработал шаг 2.** Шаг 2 ушёл на CPU (GPU упал или
     Vulkan без устройства) → диаризация сразу на CPU-сборке (macOS arm64 — тот же бинарник с
     `PARAKEET_DEVICE=cpu`). В прогоне не больше одной пустой GPU-попытки;
   - шаг 2 прошёл на GPU, а диаризация на GPU упала (ненулевой код) → повтор на CPU;
   - таймаут — тот же `LOCAL_TIMEOUT_MS`; таймаут на GPU не повторяется на CPU;
   - `--threads` у `scene` нет — не передаём.
4. Привязка слов к спикерам, cues.

Проходы последовательные: на GPU оба укладываются в секунды, на CPU параллельный запуск делил
бы те же ядра.

### `src/local/diarize.ts`

- `type Segment = { speaker: number; start: number; end: number }`.
- `parseScene(stdout: string): Segment[]` — построчно `JSON.parse`, собирает `speakers` всех
  событий; пустые строки пропускает. Строка не JSON или сегмент не той формы → бросает
  ошибку (её ловит вызывающий и превращает в note).
- `assignSpeakers(words: Word[], segs: Segment[]): (number | null)[]` — для каждого слова:
  1. сегмент с максимальным пересечением `[word.start, word.end]` (при равенстве — более ранний);
  2. иначе ближайший сегмент, если расстояние до него ≤ 0.5 с;
  3. иначе спикер предыдущего слова; у слов в начале без предыдущего — спикер первого
     следующего слова, получившего спикера;
  4. сегментов нет вовсе → `null` у всех.
- `runDiarization(...)` — запуск `scene` по правилам устройства выше, возвращает сегменты,
  фактическое устройство и время процесса.

### Метки и cues

- Номера движка превращаются в `Speaker 1..N` по первому появлению **среди слов**; спикер, не
  получивший ни одного слова, не считается.
- `wordsToCues` принимает слова с необязательным спикером и дополнительно режет cue на смене
  спикера. Абзацы — существующий `toParagraphs` (уже режет на смене спикера).
- **Два и больше спикеров**: cues со `speaker`, `diarized: true`, `speakers: N`.
- **Один спикер**: cues без `speaker` (транскрипт как без диаризации), `diarized: true`,
  `speakers: 1` — проверка была, найден один.
- Слова без спикера (сегментов нет) — `diarized: false`, `speakers: 0`, note
  `<provider>: speaker labels skipped — no speech segments found`.

### Ошибки диаризации — не фатальны

Транскрипт выходит без меток (`diarized: false`, `speakers: 0`), в `notes` (→ `asr_failed`):
- модель не установлена: `<provider>: speaker labels skipped — diarization model not installed, run \`local install\``;
- `scene` упал на CPU (или на GPU и затем на CPU):
  `<provider>: speaker labels skipped — diarization failed (<последняя строка stderr>)`;
- таймаут: `<provider>: speaker labels skipped — diarization timed out`;
- неожиданный вывод: `<provider>: speaker labels skipped — unexpected parakeet-cli scene output`.

Диаризация на GPU упала, на CPU прошла — note `<provider>: GPU diarization failed (<…>), used CPU`.

### Подсказка про устройство

Note Vulkan без устройства становится:
`<provider>: no GPU device found, ran on CPU — set "device": "cpu" for <provider> to skip the GPU attempt`.

### `AsrResult`

Новое необязательное поле
`diarization?: { device: "gpu" | "cpu"; plannedDevice: "gpu" | "cpu"; elapsedMs: number; pathElapsedMs: number }`
— для учёта скорости (см. ниже): `elapsedMs` — время успешного запуска `scene`,
`pathElapsedMs` — от первой попытки диаризации (включая упавшую GPU-попытку). Есть только при
успешном проходе диаризации.

## whisperx: один спикер без меток

`parseWhisperx` при ровно одном найденном спикере возвращает cues без `speaker`,
`diarized: true`, `speakers: 1`. Запрос к серверу не меняется. Сохранённые транскрипты не
переписываются (правило действует при новом `fetch` или `--force`).

## Скорость и `--accept-slow`

- Отдельный ключ хранилища: `parakeet:diar:<gpu|cpu>` (рядом с `parakeet:ultra:<…>`).
- Значения по умолчанию до первого замера: CPU **16×**, GPU **100×**.
- После успешной диаризации `fetch-cmd` записывает `длительность / elapsedMs` под ключ
  фактического устройства; если планировался GPU (`plannedDevice`), а прошла на CPU, — ещё и
  `длительность / pathElapsedMs` под ключ `gpu` (как у распознавания: оценка читает
  планируемый ключ). `plannedDevice` диаризации — планируемое устройство всего прогона.
- `estimateLocal` = время распознавания + время диаризации. Вторая часть — только если
  диаризация будет: нет `--no-diarize`, `provider.diarize`, модель на месте (по размеру).
  Устройство диаризации в оценке — то же планируемое устройство.
- `SlowEstimate` получает `withoutDiarization?: number` (минуты без неё).
- Текст отказа:
  - с диаризацией выше порога, без неё — не выше:
    `~12 min on CPU with speaker labels (~6 without); add --accept-slow to wait, or --no-diarize to skip speaker labels`;
  - выше порога и без неё:
    `~25 min on CPU with speaker labels (~18 without); add --accept-slow to wait`;
  - без диаризации — как в v0.4.
- Порог — `SLOW_MINUTES = 10`; серверы не ограничиваются.

## Вывод `fetch`: предупреждения конфига

`main` загружает конфиг для `fetch` с массивом `warnings` (как `check`) и передаёт его в
`fetchCmd`. Непустой массив попадает в результат полем `warnings: string[]` (и при раннем
возврате «текст уже есть»). Поля meta не меняются.

## Тестирование

Юнит-тесты (`bun test`) с подменой `run`/`fetch`/ФС, как в v0.4:
- `parseScene`: фикстура — обрезанный реальный JSONL (только поля и числа, без текста);
  пустые строки; битая строка; сегмент не той формы;
- `assignSpeakers`: максимальное пересечение, ничья, допуск 0.5 с, наследование от
  предыдущего, начало без предыдущего, пустые сегменты;
- метки: нумерация по первому появлению, спикер без слов исчезает, один спикер без меток;
- `wordsToCues`: разрез на смене спикера; старые правила (пунктуация, пауза, 30 с) не тронуты;
- `transcribeParakeet`: порядок и аргументы проходов; диаризация на устройстве шага 2
  (GPU ok; GPU упал; Vulkan без устройства); GPU-диаризация упала → CPU; все note-ветки;
  `--no-diarize`/`diarize: false`/нет модели — `scene` не запускается; поле `diarization`;
- install: модель диаризации качается и проверяется; идемпотентность; докачка: `206`
  дописывает, `200` начинает заново, 3 попытки исчерпаны, 4xx без повтора, превышение
  размера без повтора; результат с `diar_model`;
- status: поле `diarization`; `check` — необязательный пункт `diarization-model`;
- конфиг: `diarize` у local (true/false/не булево), по умолчанию `true`;
- скорость: сумма проходов, значения по умолчанию, запись ключа `diar` (включая
  планируемый `gpu`), тексты отказа (три случая);
- whisperx: один спикер → без меток, `diarized: true, speakers: 1`; два — как раньше;
- `fetch`: `warnings` в результате (и при раннем возврате);
- регрессия: существующие тесты local/whisperx/openai-compatible проходят.

Ручная приёмка на реальном движке (Linux x64, Vulkan и CPU):
- `local install` на машине с v0.4 докачивает только модель диаризации;
- `fetch` ролика с двумя спикерами (есть эталон whisperx) — сверка меток разовым скриптом
  вне репозитория;
- монолог — без меток, `speakers: 1`;
- `--no-diarize` и `"diarize": false` — `scene` не запускается;
- `"device": "cpu"` — оба прохода на CPU, замеры под ключами `cpu`;
- длинное видео на CPU — отказ с двумя цифрами;
- macOS (Metal) — проверяет владелец репозитория.

## Открытые вопросы на реализацию

- Сколько реально стоит диаризация на CPU на длинных записях (16× против 77× в пробах) —
  значение по умолчанию поправить по замеру, если разница подтвердится.
- Ведёт ли себя `scene` на Metal так же (строка устройства в stderr, код выхода) — проверка
  на Mac; пока для Metal действует правило «код выхода», как у `transcribe`.
