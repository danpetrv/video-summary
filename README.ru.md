# video-summary

[English](README.md) · **Русский**

Скилл в формате [Agent Skills](https://agentskills.io): превращает ссылку на YouTube,
ссылку на видео с другого сайта или локальный аудио/видеофайл в структурированное
саммари в markdown. CLI достаёт текст (ручные субтитры, по желанию автосубтитры, или
распознавание речи прямо на вашей машине), саммари пишет ваш агент, а затем его можно
отправить в [Readeck](https://readeck.org).

## Установка

```sh
npx skills add danpetrv/video-summary
# или: pnpm dlx skills add danpetrv/video-summary
```

Дальше попросите агента: `/video-summary https://youtu.be/...`. При первом запуске агент
проведёт настройку: папка для результатов, распознавание речи, язык, размер саммари,
Readeck. Для распознавания он предложит локальный движок: с вашего согласия скачает его
один раз (около 1 ГБ: модель Parakeet Ultra, модель разметки спикеров и бинарники
parakeet.cpp). Аккаунт и API-ключ не нужны.

## Использование

```
/video-summary <url|путь> [размер] [провайдер]
```

| аргумент | значения | по умолчанию |
|---|---|---|
| `<url\|путь>` | ссылка на YouTube, ссылка на другой сайт, который знает yt-dlp, или путь к локальному аудио/видеофайлу | обязателен |
| `размер` | `short`, `medium`, `long` или время чтения `1m`…`60m` | `summaryLength` из конфига (`medium`) |
| `провайдер` | `name` провайдера распознавания из конфига, например `local` | провайдеры по порядку из конфига, с запасными |

Необязательные аргументы можно указать в любом порядке или не указывать вовсе. Можно и
просто сказать словами, на любом языке: «кратко», «подробно», «на 5 минут чтения»,
«распознай локально».

```
/video-summary https://youtu.be/dQw4w9WgXcQ
/video-summary https://youtu.be/dQw4w9WgXcQ short
/video-summary ~/Videos/lecture.mp4 10m local
```

### Размер саммари

| размер | что входит в саммари | время чтения |
|---|---|---|
| `short` | шапка, TL;DR и ключевые идеи (5-8 пунктов) | около 1-2 мин |
| `medium` | весь шаблон: шапка, TL;DR, содержание с таймкодами, разбор по разделам, ключевые идеи, а также цитаты, упомянутое и схема, если в видео есть что туда положить | зависит от видео |
| `long` | весь шаблон, подробно: более дробное содержание, в каждом разделе аргументы, примеры, цифры и кто что сказал; цитаты и упомянутое щедро | больше, чем у `medium` |
| `<N>m` | целевое время чтения N минут (1-60): при N ≤ 2 структура `short`, иначе структура `medium`, глубина подгоняется под N | ≈ N мин |

Размер берётся сначала из аргумента запроса, затем из формулировки («кратко» → `short`,
«подробно» → `long`, «на 5 минут чтения» → `5m`), затем из `summaryLength` в конфиге. При
`<N>m` агент после написания проверяет реальное время чтения и, если оно расходится с N
больше чем примерно на 30%, один раз сокращает или дополняет саммари.

TL;DR всегда занимает 3-5 пунктов. Саммари пишется на языке `summaryLanguage` (`auto` —
на том языке, на котором вы говорите с агентом), даже если видео на другом языке. Для
YouTube таймкоды — ссылки на нужный момент видео.

### Провайдер распознавания

Имя провайдера в запросе (`/video-summary <url> local`, «распознай локально», «через мой
сервер») означает: распознать это видео только этим провайдером, без перехода на
остальные. Если он недоступен или упал, вы получите причину, а не транскрипт от другого
провайдера. Субтитры при этом всё равно в приоритете: распознавание запускается, только
когда их нет. Сами провайдеры описаны в разделе
[Распознавание речи](#распознавание-речи).

### Что получится

Для каждого видео создаётся папка `<outputDir>/<дата>-<название>/`:

- `transcript.md` — полный текст с таймкодами и метками спикеров (если они есть);
- `summary.md` — саммари;
- `meta.json` — название, канал, длительность, источник текста и прочее.

Повторный запрос того же видео использует ту же папку: транскрипт заново не скачивается,
а агент спрашивает, переписать ли саммари (в новом размере, если вы его указали). Если
настроен Readeck, саммари сохраняется ещё и туда, закладкой с превью видео.

Текст берётся из первого источника, где он есть:

1. ручные субтитры с сайта;
2. для локального файла — файл субтитров рядом с ним: `name.srt`, `name.vtt` или
   `name.<язык>.srt|vtt`;
3. автосубтитры YouTube, только при `"subtitles": "manual+auto"`;
4. распознавание речи.

## Требования

- `yt-dlp` (с extra `[default]`, ради `yt-dlp-ejs`) и `ffmpeg`/`ffprobe`; для YouTube
  yt-dlp использует deno, node или bun как JavaScript-рантайм (что из них установлено)
- `bun` или Node.js >= 20 (скилл поставляется с готовым бандлом, `npm install` не нужен)
- macOS (Apple Silicon; на Intel-маках работает на CPU) или Linux (x64, arm64); на Windows —
  через WSL2, он считается Linux
- для локального распознавания на GPU под Linux: загрузчик Vulkan (`libvulkan1` в
  Debian/Ubuntu) и рабочий драйвер видеокарты; без них распознавание идёт на CPU

Агент проверяет всё это сам (`check`) и предлагает поставить недостающее.

## Распознавание речи

Распознавание нужно, когда у видео нет субтитров. Провайдеры перебираются в порядке
конфига, берётся первый подходящий. Если он упал во время распознавания (ошибка сервера,
сеть, сбой локального движка), пробуется следующий подходящий. Чтобы распознать видео
одним конкретным провайдером, назовите его в запросе (см.
[Провайдер распознавания](#провайдер-распознавания)).

| провайдер | что это |
|---|---|
| `local` (рекомендуется) | Parakeet Ultra через [parakeet.cpp](https://github.com/mudler/parakeet.cpp) на этой машине: без сервера и ключа; GPU (Metal на Apple Silicon, Vulkan на Linux) или CPU; 25 европейских языков; метки спикеров (до 8) |
| `whisperx` | ваш собственный сервер [whisperx-asr-service](https://github.com/murtaza-nasir/whisperx-asr-service), с метками спикеров |
| `openai-compatible` | ваш собственный OpenAI-совместимый сервер (speaches, faster-whisper-server, ...) через `url` + `model` |

**Языки.** Локальный движок знает bg, hr, cs, da, nl, en, et, fi, fr, de, el, hu, it, lv,
lt, mt, pl, pt, ro, sk, sl, es, sv, ru и uk; видео на другом языке уходит следующему
провайдеру в списке.

**Скорость.** Зависит от железа: десктопная видеокарта распознаёт час аудио меньше чем за
минуту, CPU — за несколько минут и дольше. Если распознавание займёт больше 10 минут,
агент назовёт оценку (по скорости, замеренной на вашей машине) и дождётся вашего
согласия.

**Метки спикеров.** Локальный движок по умолчанию размечает спикеров вторым проходом по
аудио (небольшая дополнительная модель, около 0,1 ГБ, её скачивает `local install`). У
видео с одним спикером меток нет. Чтобы обойтись без меток, скажите, что говорит один
человек, или поставьте провайдеру `"diarize": false`; на CPU это ещё и ускоряет работу.
Если разметка не удалась, вы получите транскрипт без меток и объяснение почему. При
обновлении с v0.4 докачивается только эта модель.

## Конфиг

`${XDG_CONFIG_HOME:-~/.config}/video-summary/config.json`; `$VIDEO_SUMMARY_CONFIG`
задаёт путь целиком. Агент создаёт конфиг при первой настройке; чтобы потом что-то
поменять, попросите агента или выполните `config set <ключ> <json>`.

```json
{
  "outputDir": "~/Documents/video-summaries",
  "summaryLanguage": "auto",
  "summaryLength": "medium",
  "subtitles": "manual",
  "providers": [
    { "name": "home-whisperx", "type": "whisperx", "url": "https://asr.example" },
    { "name": "local", "type": "local" }
  ],
  "readeck": { "url": "https://read.example", "keyFile": "~/.config/video-summary/readeck.key" }
}
```

Здесь первым пробуется ваш whisperx-сервер, а локальный движок — запасной.

| ключ | значения | по умолчанию |
|---|---|---|
| `outputDir` | папка для саммари и транскриптов | `~/Documents/video-summaries` |
| `summaryLanguage` | `auto` (язык, на котором вы говорите с агентом) или код: `ru`, `en`, ... | `auto` |
| `summaryLength` | `short`, `medium`, `long` или `<N>m`; размер в запросе важнее | `medium` |
| `subtitles` | `manual` или `manual+auto` — тогда перед распознаванием берутся и автосубтитры YouTube (в них бывают ошибки) | `manual` |
| `providers` | провайдеры распознавания в порядке приоритета; пустой список — только субтитры | `[]` |
| `readeck` | `{url, keyFile \| keyEnv, label?}` или `null`, чтобы отключить отправку | `null` |

Поля провайдера:

| поле | у каких провайдеров | смысл |
|---|---|---|
| `name` | у всех | уникальное имя, по нему провайдер выбирается в запросе |
| `type` | у всех | `local`, `whisperx` или `openai-compatible` |
| `url` | у серверов | адрес сервера; для `openai-compatible` заканчивается на `/v1` |
| `model` | `openai-compatible` | id модели, загруженной на сервере, например `Systran/faster-whisper-large-v3` |
| `keyFile` / `keyEnv` | у серверов и `readeck` | файл с ключом или переменная окружения; сам ключ в конфиг не попадает |
| `diarize` | `local`, `whisperx` | `false` отключает метки спикеров (по умолчанию `true`) |
| `device` | `local` | `cpu` — никогда не использовать GPU (по умолчанию `auto`) |

Закладка в Readeck получает метку `video-summary` (или `label` из конфига) и превью видео
в качестве картинки; для локального файла в текст вставляется первый не чёрный кадр первой
минуты (или обложка аудиофайла).

Локальный движок хранит файлы в `${XDG_DATA_HOME:-~/.local/share}/video-summary/`
(бинарники), `${XDG_CACHE_HOME:-~/.cache}/video-summary/models/` (модели) и
`${XDG_STATE_HOME:-~/.local/state}/video-summary/speed.json` (замеренная скорость).

## Справка по CLI

Обычно CLI запускаете не вы, а агент. Сами команды пригодятся для отладки и скриптов.
Запуск — через лаунчер, он выбирает bun или node:

```sh
sh <skill-dir>/scripts/video-summary <команда>
```

Каждая команда печатает JSON в stdout; при ошибке выходит с кодом 1 и пишет одну строку в
stderr.

| команда | что делает |
|---|---|
| `check` | проверяет зависимости, конфиг, провайдеров и Readeck |
| `config path` | печатает путь к конфигу |
| `config get [ключ]` | печатает конфиг целиком или один ключ (работают пути вида `readeck.url`) |
| `config init [--force]` | создаёт конфиг по умолчанию; `--force` перезаписывает существующий вместе с провайдерами и настройками Readeck |
| `config set <ключ> <json>` | задаёт один ключ; значение — JSON (`'"short"'`, `'[...]'`, `null`), оно проверяется |
| `fetch <url\|путь> [флаги]` | достаёт текст в `<dir>/transcript.md` |
| `finalize <dir>` | проставляет время чтения в `summary.md` |
| `readeck <dir>` | отправляет саммари в Readeck |
| `local install` | скачивает локальный движок и модели (около 1 ГБ); повторный запуск безопасен |
| `local status` | показывает, что из локального движка установлено, без сети |

Флаги `fetch`:

| флаг | смысл |
|---|---|
| `--provider <name>` | распознавать только этим провайдером, без запасных |
| `--no-diarize` | без меток спикеров (быстрее на CPU) |
| `--accept-slow` | запустить локальное распознавание, даже если по оценке оно займёт больше 10 минут |
| `--force` | скачать и распознать заново, а не вернуть уже готовый транскрипт |

## Приватность

Субтитры скачиваются прямо с сайта. Аудио распознаётся только на ваших машинах: локальным
движком или вашим собственным сервером, если вы его настроили (куда указывает `url`
сервера, скилл не проверяет). Ключи от ваших серверов хранятся в файлах ключей или
переменных окружения и никогда не попадают в конфиг и в вывод.

## Разработка

```sh
bun install
bun test
bun run check:bun-free   # в src/ можно использовать только API node:*
bun run build            # пересобирает skills/video-summary/scripts/video-summary.mjs
```

Бандл лежит в репозитории, и CI проверяет, что он совпадает со свежей сборкой, поэтому
версия bun закреплена вместе с ним (`bun-version: 1.4.2` в `.github/workflows/ci.yml`);
поднимайте обе сразу.

### Релизы

Слейте изменения в `main` и запушьте тег:

```sh
git tag -a v0.1.3 -m "v0.1.3" && git push origin v0.1.3
```

`.github/workflows/release.yml` прогоняет проверки CI и создаёт релиз на GitHub. Заметки
собираются из коммитов с предыдущего тега (`bun scripts/release-notes.ts <tag>` показывает
их заранее): `feat:` → Features, `fix:` → Fixes, остальное → Other, коммиты `build:`
пропускаются, а `Fixes #N` в теле коммита превращается в ссылку. Тег с суффиксом
(`v0.2.0-rc.1`) становится пре-релизом.

`npx skills add danpetrv/video-summary` ставит `main`; конкретный релиз закрепляется так:
`npx skills add danpetrv/video-summary#v0.1.2`.
